Sale Return & Credit Wizard

Handle customer returns, cancellations and credit notes for any line of a Sale Order from a single popup. The wizard creates the return receipt, the credit note and the order changes in one step, and only credits what was actually invoiced.

Why this module

Handling a customer return in standard Odoo works, but it takes three apps and many manual steps, and it is easy to get wrong when an order has many lines, several deliveries or partial invoices.

In standard Odoo 19

  • Returns start from one delivery at a time. With several deliveries per order you must find the right one first.
  • The return screen lists stock moves with no search, no filter and no view of what was invoiced.
  • The credit note is a separate step: create it from the order or the invoice, then check each line against what came back.
  • For products invoiced on ordered quantities, the order quantity, the pending delivery and the credit note must all be fixed by hand.
  • A credit note reversed from the invoice stays linked to the order, so a goodwill credit makes the quantity invoiceable again.
  • Nothing ties the return, the credit note, the order change and the reason together in one audit record.

With this module

  • One Return / Credit button on the Sale Order and on each customer delivery.
  • Every order line in one table with ordered, delivered, invoiced, returnable and undelivered quantities.
  • Search and filter by product, SKU, barcode, description or quantity range. Built for orders with hundreds of lines.
  • One click creates the return receipt, the credit note (posted or draft) and reduces the order and its pending delivery.
  • Credit is limited to the invoiced part of each line, and Credit Only allowances never reopen the order for invoicing.
  • An SRET log links the order, the delivery, the return receipts, the credit notes and the reason.

How it works

1
Open
Click Return / Credit on a confirmed Sale Order or a customer delivery.
2
Filter
Find the lines concerned by name, SKU or quantity. The list filters as you type.
3
Choose
Set an action and a quantity per line, or use a bulk button on the lines shown.
4
Process
Return receipt, credit note and order changes created, log written, popup closed.

Features

All screenshots are from a live Odoo database with demo data: order S00029, 10 lines, partly delivered and invoiced.

Feature 1

Return / Credit button on the Sale Order

Shown on confirmed orders to users in the Returns & Credit Notes group (Sales Managers get it automatically). Quotations, cancelled and locked orders do not show it. A Returns smart button appears once the order has a return log.

Feature 2

Every order line in one table

Each line shows Ordered, Delivered, Invoiced, Returnable and Undelivered quantities, combined across all deliveries and invoices of the order. The header shows how many lines are shown and selected, and the estimated credit, updated as you edit.

Feature 3

Search and filter large orders

Filter by product name, SKU, barcode or line description (comma-separated terms match any of them), by a quantity range on Ordered, Delivered, Invoiced, Returnable or Undelivered, or show only actionable or selected lines. The list filters as soon as a filter changes, and edits on hidden lines are kept.

Search “chair” matches product names and line descriptions: 3 of 10 lines shown.
Quantity = Undelivered (above 0): 2 of 10 lines shown.
Feature 4

Bulk actions on the lines shown

Return all returnable, Credit all invoiced, Cancel all undelivered and Keep all apply the maximum allowed quantity to every line currently shown, and skip lines where the action has nothing available. Here the two backordered lines are set to Cancel Undelivered in one click.

Feature 5

One action per line, with its own limit

Pick an action and the quantity fills in with the maximum allowed; lower it if needed. Max shows the limit for that action and Credit previews the untaxed amount, at the line's price and discount.

Keepnothing changes on the line
Return & Refundgoods come back, up to the delivered quantity not yet returned
Credit Onlyprice allowance, the customer keeps the goods, up to the invoiced quantity not yet credited
Cancel Undelivereddrop what has not shipped yet, up to ordered minus delivered
Feature 6

Quantities can never exceed what was ordered, delivered or invoiced

A quantity above the limit is capped while you type, with a message that explains why. Server-side constraints block negative values, quantities on Keep lines and anything above ordered, delivered, still-returnable or still-creditable. On Process, every line is re-read from the live order, so a return made meanwhile by a colleague is never duplicated.

Feature 7

Review before anything is created

Switch on Only Selected to see exactly what will be processed and its total credit. Add a reason, choose whether to receive the goods now and whether to post the credit note, then click Process. Cancel closes the popup and nothing is created.

Features 8 & 9

An exact credit note and a validated return receipt

One click here produced a posted Customer Credit Note for $315.00 (3 returned lamps, a 1-chair allowance and 5 over-invoiced drawers), with the reason as its reference and a link to the original invoice. The return receipt was created with Odoo's standard return mechanism against the original delivery, so valuation and traceability follow core rules, and it was validated straight away. The undelivered backorder was cancelled and the order quantities updated.

Feature 10

Audit trail: Returns & Credits

Every run writes an SRET/YYYY/NNNNN record that cannot be created or edited by hand. It holds the user and date, the reason, the amount credited and, per line, the quantity asked, credited, received back and removed from the order, with smart buttons to the return receipts and credit notes. Status stays Waiting Goods until the warehouse validates the returns. Find it under Sales › Orders › Returns & Credits, filtered by Waiting Goods or My Returns and grouped by customer or date.

Feature 11

Summarised in the order's chatter

The Sale Order receives a message linking to the log, with one line per action, next to Odoo's own tracking of the changed quantities and totals.

Feature 12

Start from a delivery too

The same button sits next to Odoo's Return on every customer delivery of a confirmed order. From a delivery, the wizard lists only that delivery's products and caps every limit to what this transfer shipped or still has open. Cancelling from a backorder cuts that backorder's own moves, never another delivery. A Return Logs smart button and chatter messages appear on the delivery.

Automatic routing

Each line is routed by what was delivered and invoiced for it. You never choose the documents by hand.

Return credit = min(Q, I)  ·  Cancel credit = min(Q, max(0, I − (O − Q)))  where Q = quantity, O = ordered, I = invoiced and not yet credited.
Example: ordered 20, invoiced 20 in advance, cancel 5 undelivered → 15 stay ordered against 20 invoiced, so 5 are credited. Quantities on posted invoices go to a posted credit note; quantities found only on draft invoices go to a draft one.

Built for real-world corner cases

Several deliveries per order
Returns are taken from the newest deliveries first, with one return receipt per original delivery.
Stale wizards
Quantities are re-read on Process, and a popup left open while the order changed is refused with a clear message.
Pending returns
Returns not yet validated are deducted from what can still be returned.
Receive later
Lot/serial-tracked goods, or Receive Now switched off, leave the receipt to the warehouse; the order is updated when it is validated, even by a user without sales rights.
Invoice on ordered quantities
Cancelling undelivered goods credits the part that becomes over-invoiced.
Repeated allowances
Credit Only quantities are remembered, so the same units can never be credited twice.
Multi-step deliveries
From a backorder, upstream pick and pack moves are reduced too; quantities already processed are never cancelled.
Unusual transfers
Receipts, internal transfers, dropships, returns and lines from another order are refused or listed separately, with a reason.
Security & multi-company
A dedicated group controls access, inventory rights are checked for returns, and record rules apply per company.
